## Corrected first-run failure/partial preservation, private only

Original PR15 v1.1 in-memory four-hour poll/tick core would lose most raw partial evidence on errors and permit an easily discarded abort. This descendant introduces:

1. `demo_adapter/scripts/v12_attempt_journal.py`: before any MT5 import/initialize (after exact offline contract/owner checks), exclusive-create private `v12-attempt-<EXACT_REGISTRATION_SHA256>.jsonl`, writes `ATTEMPT_STARTED` and fsyncs. Cannot create same registration a second time under the pinned private directory. Each JSONL line carries ordinal, previous SHA, canonical event SHA256 and UTC time; every write is flushed and fsynced, including fatal exit. No raw account login/secret or credentials in journal. This **does not** independently authenticate the file origin against administrator tampering; requires independent owner archive.
2. `demo_adapter/scripts/v12_journaled_readonly_port.py` decorates only allow-listed read-only APIs and writes each polled XAUUSD bid/ask/time_ms and each true-tick chunk (source row ordinal, time, MT5 flags) durably *before* supplying it to frozen v1.1 core. Also records terminal connected/tradeapi_disabled, zero position/order count read checks and symbol read presence. A slow/short fsync or missing source FAILS the capture rather than skipping an unknown interval.
3. Host `v12_windows_mt5_readonly_host.py` runs the journal from before MT5 initialize, wraps the read-only port, records `FAIL_CLOSED` by exception type (sanitized, no broker secrets), and only after immutable private successful raw output plus Python attachment shutdown records `COMPLETED_RAW_NOT_ADMITTED` with the raw SHA. A killed process has no terminal event => verifier classifies `INCOMPLETE_FAIL_CLOSED`; **neither state may ever be called PASS or retried under that exact registration**. All prior failures remain unchanged. Unknown position exposure is **human-only E1**, no automatic closure.
4. One PS5.1 collector `v12-readonly-collector.ps1` source-pins journal modules and checks for an already-used registration before any attach. Independent PS5.1 verifier `v12-readonly-verifier.ps1` checks SHA and calls **offline** Python journal verification against exact raw SHA; FAIL_CLOSED or missing/truncated/modified journal denies a clean capture and no admissible calibration results. It prints private attempt SHA to be archived, not uploaded raw to GitHub.
5. `tests/test_v12_immutable_attempt_journal.py` synthetic tests assert explicit FAIL/CANCEL, missing-final, truncated line, source tamper, last-success-only, same-registration rerun denial and partial quote + tick flags. Both code pins and changed host/PS hashes are **new** and published in GitHub manifest `phase0/roadmap/DEMO_V12_READONLY_SOURCE_SHA256_PIN_MANIFEST_2026-10-19.json`. The old PR15 hash trio is **REVOKED for future execution** (historically valid only for PR15 source). All 9 pinned files use LF checkout and are subject to exact SHA256 independent tests and Windows PowerShell native parser CI.

**Important limit:** an attacker with private administrator access could rewrite a hash chain; this mechanism is crash/accident protection, not a notarized, external append-only attestation. Private attempt journal and raw output must be preserved/archived independently after any run, including failure. The extra fsync adds polling overhead; missed slots fail closed rather than letting the run pass. A host that loses power during initial directory creation might leave a malformed file; the next attempt with same registration still rejects reuse.
