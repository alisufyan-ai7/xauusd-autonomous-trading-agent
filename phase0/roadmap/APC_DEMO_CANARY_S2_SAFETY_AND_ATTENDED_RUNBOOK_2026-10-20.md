## Audit of old PR23 code — why a new successor was necessary

1. **Post-entry side, origin and deal binding defect:** old PR23 verified symbol, volume, stop and ticket but not matching BUY/SELL side, canary magic, bounded actual fill or positive deal ID. A mismatch could have been incorrectly accepted as the owner canary. **S2** denies on any mismatch, records `UNCERTAIN`, persists `QUARANTINED`, no automatic retry/closure of unknown position. Close also validates exact ticket, magic, direction, volume, stop, a positive deal ID and flat account. The presence of a positive deal ID is necessary but not a complete broker history audit; explicit human confirmation remains required.
2. **Unbound market entry price:** old operator accepted side+SL without an owner-defined price ceiling/floor. S2 requires a numeric `--price-limit` in addition to exact owner-specified side and protective stop. BUY requires `ask + 20*point <= ceiling`; SELL requires `bid - 20*point >= floor` before order_check/send. Actual `price_open` checked against the bound and within $0.20 from submitted order price. This binds the owner APC to a bounded execution price, not a stale quote. Quotes/MT5 fill are asynchronous; if fill violates the bound, quarantine and human reconcile, do not auto retry.
3. **Isolated package resolution:** staged `site` wheels are not globally installed. S2 code embeds the isolated loader `demo_adapter/scripts/apc_demo_canary_s2_isolated_loader.py` and PS5.1 launcher in a **NEW** sealed artifact, without modifying the old stage. The loader compares the exact head and sealed ZIP digest supplied in the separately owner-reviewed command, verifies manifest and all component file hashes, checks unpacked site files byte-for-byte and rejects extras/duplicate wheel members, validates persisted SQLite gate, injects `site` into this interpreter only, and uses the exact archived operator. No global pip, Python-path persistence or daemon. Any tamper/missing candidate => FAIL_CLOSED before MetaTrader5 import.
4. **Unknown results are never retried:** durable entry `ENTRY_IN_FLIGHT` reserved before `order_send`; after confirmed deal+position -> `OPEN`; any unexpected acknowledgment, missing deal ID, mismatch or unconfirmed exposure -> `UNCERTAIN` and `QUARANTINED`. Close requires `ACTIVE` / journal `OPEN` and exact same known ticket; it reserves `CLOSE_IN_FLIGHT` before one close attempt. Unknown close result -> `UNCERTAIN` / `QUARANTINED` and **no automatic second close**. Human will inspect exact account/position/order/deal history; NEVER interpret lack of response as unfilled.
5. **Risk remains DEMO_CANARY_ONLY:** frozen `0.01` lot, exact `XAUUSD`, stop mandatory and tick-aligned, symbol `trade_tick_value_loss` independently matched to USD contract/tick and `order_calc_profit`, loss = upward-rounded worst-fill-to-stop+slippage `0.50` USD/oz + stop-gap `2.00` USD/oz + commission `$5` and swap `$2` per trade, cap = floor(min($25,0.25% of min(equity,balance,$10k))), current+2× stressed M1≥1000%, free margin ≥90% equity. Synthetic model is **NOT** maximum realized-loss insurance and **NOT** admissible for real money.
6. **Account selection:** S2 code has NO `mt5.login`, `account_select` or broker-switch path; every action rechecks `ACCOUNT_TRADE_MODE_DEMO`, exact Exness company/server/currency, SHA256 of account identity, terminal connectivity, symbol, order budget and current exposure. A racing external user/account switch is a residual operational risk; the human must use a **dedicated demo-only MT5 terminal/session without live credentials**, verify exact account immediately before the one entry and again before the known close, and stop if uncertain. A code-side check alone cannot absolutely prevent a concurrent manual account switch.
7. **Timeout and emergency:** control permit is bounded and does not create any unattended auto-close. If an owner close cannot be completed within permitted window, do **NOT** re-arm, reset journal, or repeat an unknown order. Disable external-Python trading in terminal; human inspect the exact Exness DEMO account and position. If ticket/side/volume/SL are positively known, manually close via broker UI if appropriate and independently record broker flat + history and local control state. If exposure unknown, keep QUARANTINED and contact broker/owner for reconciliation; no automatic unknown-exposure closure.
8. **Terminal trade toggle:** the Python operator does not and cannot credibly promise to change the MT5 GUI safety setting. Only the owner, in the **future single exact APC-DEMO-CANARY attended session**, may temporarily uncheck `Disable automated trading via external Python API` (actual UI wording may vary), supervise entry/close, then **recheck** and verify it is enabled again (external Python DISABLED). If any exception: prioritize disabling external-Python trading and inspect broker exposure; do not claim KILLED/flat without reconciliation. Do not use scheduled tasks or unattended automation.
